[HIGH] INCORRECT_LOGIC
Description: AbstractBlockCreator computes the new header's excessBlobGas from parentHeader excess plus the blob count of transactions selected for the current block (newBlobsCount -> blobGasCost(newBlobsCount)). The spec defines header excess_blob_gas as the value prior to the block, derived only from the parent header. This also conflicts internally with ExcessBlobGasCalculator.calculateExcessBlobGasForParent, which correctly uses parent blobGasUsed. On the next block, calculateExcessBlobGasForParent would add the same parent blob gas again, double-counting it.
Spec ref: def calc_excess_blob_gas(parent: Header) -> int: if parent.excess_blob_gas + parent.blob_gas_used < TARGET_BLOB_GAS_PER_BLOCK: return 0 else: return parent.excess_blob_gas + parent.blob_gas_used - TARGET_BLOB_GAS_PER_BLOCK; excess_blob_gas is a running total of blob gas consumed in excess of the target, prior to the block.
Location: ethereum/blockcreation/src/main/java/org/hyperledger/besu/ethereum/blockcreation/AbstractBlockCreator.java: computeExcessBlobGas(TransactionSelectionResults, ProtocolSpec), approx. line 350; also evm/src/main/java/org/hyperledger/besu/evm/gascalculator/CancunGasCalculator.java: computeExcessBlobGas(long,int)
Impact: Locally created blocks can have an excess_blob_gas that other clients and the spec validator reject, causing consensus/proposal failures. If accepted by similarly incorrect nodes, blob gas prices drift upward too quickly because current-block blob use is counted twice.
Fix: In AbstractBlockCreator, set header excessBlobGas using calculateExcessBlobGasForParent(newProtocolSpec, parentHeader) / parent excess plus parent blobGasUsed only, while setting blobGasUsed separately from the current block's selected blobs. Remove or rename the ambiguous int-count overload so callers cannot confuse blob count, current-block gas, and parent gas.
